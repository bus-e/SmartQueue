# SmartQueue

Электронная очередь в приложении, на сайте и в Telegram-боте. Один сервер и одна база: очередь одна и видна везде.

## Состав

| Папка | Что это |
|---|---|
| `server/` | API-сервер: FastAPI, правила очереди (`app/domain`), миграции Alembic |
| `deploy/` | Настройки Nginx |

## Запуск

```
cp .env.example .env
docker compose up --build
```

Проверка: http://localhost:8080/api/v1/health, описание API — http://localhost:8080/docs.

Тесты сервера:

```
cd server
pip install -r requirements-dev.txt
pytest
```

## Как работаем

- Основная ветка — `main`, в неё попадает только проверенный код.
- На каждую задачу плана — своя ветка: `z9-api-queue`, `z13-site-join`.
- Готово — запрос на слияние. Его смотрит второй участник: сервер и бот проверяет Игорь, клиент — Егор.
- Сливаем, когда тесты в GitHub Actions зелёные и замечания закрыты.
- Сообщение коммита — что сделано, одной строкой: «Добавлена передача управления по времени».
- Секреты (токен бота, пароли) — только в `.env`, в репозиторий не попадают.
