# Тест-кейсы SmartQueue

Номера те же, что в плане тестирования. «Авто» — тест есть в репозитории и идёт в CI; «Руками» — проверяется по шагам.

| № | Проверка | Шаги | Ожидаем | Как |
|---|---|---|---|---|
| Т1 | Создание обычной очереди | Создать очередь «Зачёт» | Код из 6 символов; создатель стоит первым | Авто: `test_t1_*` |
| Т2 | Код очереди | Ввести K7M2QX; K7M2Q; K7M2QXA; K0M2QX; код завершённой очереди | Первый принят, остальные отклонены с понятным текстом | Авто: `test_t2_*`, `queue_code_test.dart` |
| Т3 | Повторный вход | Встать в очередь дважды с одного устройства | Вторая запись не создаётся, позиция прежняя | Авто: `test_t3_*` |
| Т4 | Одна очередь на всех платформах | Встать на сайте; другой участник выходит в боте | Позиция на сайте меняется не позже 2 с | Руками, спринт 2 |
| Т5 | «Следующий» нажимает не первый | Второй участник отправляет запрос «Следующий» | Отказ 403 | Авто: `test_t5_*` |

## Дымовой тест

Пять проверок на каждую сборку, не дольше пяти минут:

1. `docker compose up --build` — все три контейнера запущены.
2. `/api/v1/health` отвечает `{"status": "ok"}`.
3. `/docs` открывается и показывает список запросов.
4. `pytest` в папке `server` — все тесты зелёные.
5. Клиент открывает главную, на неверный код показывает подсказку.

С третьего спринта добавляются: создать очередь, встать, увидеть позицию, выйти.
